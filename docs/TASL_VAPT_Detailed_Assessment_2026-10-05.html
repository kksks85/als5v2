Detailed Finding: SEC-001

Unauthenticated Generic Records API Operations

Critical - Confirmed
AttributeAssessment Result
CVSS v3.19.8 - AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H. Provisional source-based score pending deployed retest.
Affected areabackend/app/api/v1/records.py; generic records API operations.
CWE / OWASPCWE-862 Missing Authorization; CWE-639 Authorization Bypass Through User-Controlled Key; OWASP A01 and API1/API5.

Description and Business Impact

The collection list, single-record upsert, bulk-upsert and collection-replacement handlers accept only a database dependency. They do not declare validated session, role authorization, ownership/assignment-group scope, or CSRF protection. If deployed as reviewed, an unauthenticated network client could request resource collections and submit individual, bulk, or complete collection replacement operations. This exposes customer, user, incident, contract, correspondence and configuration data to material confidentiality, integrity and availability risk.

Code Evidence

@router.get("/{resource}") def list_records(resource: str, database: Session = Depends(get_db)): ... @router.put("/{resource}/{record_id}") def upsert_record(..., database: Session = Depends(get_db)): ... @router.post("/{resource}/bulk-upsert") def bulk_upsert_records(..., database: Session = Depends(get_db)): ... @router.delete("/{resource}/{record_id}") def delete_record(..., _: None = Depends(require_administrator), csrf: None = Depends(require_csrf), database: Session = Depends(get_db)): ...

Root Cause, Remediation and Retest

Apply validated-session dependencies to every generic route. Add server-side policy enforcement for each resource, action, role, group and ownership boundary. Require CSRF for cookie-authenticated writes. Restrict bulk/replace actions to explicitly authorized administration workflows. Retest anonymous, standard-user, group-member, approver and administrator identities across list/read/upsert/bulk/replace/delete. Anonymous calls must return 401, unauthorized calls 403, and no caller may cross resource ownership/group boundaries.

Detailed Findings: SEC-002 and SEC-003

SEC-002: Critical jspdf Production Dependency Advisory

Critical - Confirmed

The current production dependency audit identifies direct dependency jspdf as critical with a fix available. The application uses PDF/export functionality. The audit confirms package exposure; application-specific exploitation was not dynamically tested.

Required remediation: Review the upstream advisory, upgrade to a non-vulnerable release in an isolated branch, regenerate lock data, execute PDF/export regression with untrusted content, rerun the production audit, and retain the remediation evidence.

SEC-003: High xlsx and Tiptap Dependency Advisories

High - Confirmed

The audit identifies direct xlsx and the Tiptap editor chain as high. The xlsx audit information includes Prototype Pollution and ReDoS advisories and reports no automatic fix. Exploitability through specific import/editor workflows requires follow-up testing.

Required remediation: Replace or update xlsx using supported vendor guidance, enforce workbook size/time/resource limits, upgrade compatible Tiptap packages as a set, and test spreadsheet import/export and rich-text workflows. CI must block or explicitly approve critical/high production audit results.

Retest Evidence Required

1. Updated package manifest and lockfile. 2. npm audit --omit=dev --json output after remediation. 3. PDF, spreadsheet, and editor regression results. 4. Change approval and rollback record. 5. Formal risk acceptance only if an advisory cannot be resolved within seven days.

Detailed Finding: SEC-004

Incomplete HTTPS Response-Header Baseline

Medium - Observed

The standard Nginx profile sets Content-Security-Policy, X-Content-Type-Options, X-Frame-Options, X-XSS-Protection, Referrer-Policy and Permissions-Policy. The TLS profile mounted by docker-compose.https.yml specifies TLS 1.2/1.3 and CSP only. It does not declare the broader standard header baseline or HSTS. Whether an upstream gateway applies equivalent headers was not verified.

Configuration Evidence

# frontend/nginx.conf add_header X-Content-Type-Options "nosniff" always; add_header X-Frame-Options "DENY" always; add_header Referrer-Policy "strict-origin-when-cross-origin" always; add_header Permissions-Policy "geolocation=(), microphone=(), camera=()" always; add_header Content-Security-Policy "..." always; # frontend/nginx.https.conf ssl_protocols TLSv1.2 TLSv1.3; add_header Content-Security-Policy "..." always; # No matching nosniff, frame, referrer, permissions or HSTS directives observed.

Remediation and Retest

Centralize the approved header baseline in a shared include used by both HTTP/internal and HTTPS configurations. Add HSTS only after validating that all access is permanently HTTPS. At deployment, capture sanitized headers for the application, API and error responses and validate TLS certificates/ciphers separately.
