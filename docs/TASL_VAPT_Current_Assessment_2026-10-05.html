Detailed Finding: SEC-001

Unauthenticated Generic Records API Operations

Critical - Confirmed
AttributeAssessment Result
CVSS v3.19.8 (AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H), source-based provisional score pending deployed retest.
Affected Componentbackend/app/api/v1/records.py; /api/v1/records/{resource}.
CWE / OWASPCWE-862 Missing Authorization; CWE-639 Authorization Bypass Through User-Controlled Key; OWASP A01/API1.

Description and Impact

list_records, upsert_record, bulk_upsert_records, and replace_records declare only the database dependency. They lack require_session, role authorization, ownership/group scope, and CSRF validation. If deployed as reviewed, an unauthenticated network client may enumerate resource collections and submit individual, bulk, or collection-replacement requests, risking disclosure, modification, and disruption of customer, user, incident, contract, correspondence, and configuration records.

Evidence

GET /{resource}: list_records uses Depends(get_db) only. PUT /{resource}/{record_id}: upsert_record uses Depends(get_db) only. POST /{resource}/bulk-upsert: bulk_upsert_records uses Depends(get_db) only. PUT /{resource}: replace_records uses Depends(get_db) only. DELETE alone uses Depends(require_administrator) and Depends(require_csrf).

Remediation and Retest

Require a validated session for every records route, enforce server-side resource/action policy by role, group, and ownership, require CSRF for cookie-authenticated writes, and restrict bulk/replace operations to authorized administration workflows. Retest anonymous, ordinary-user, group-member, approver, and administrator accounts across every list/read/write/bulk/replace/delete endpoint. Anonymous calls must return 401; unauthorized calls must return 403.

Detailed Findings: Dependencies

SEC-002: Critical jspdf Production Dependency Advisory

Critical - Confirmed

The current production audit identifies direct dependency jspdf as critical with a fix available. The application includes PDF/export functionality; actual application-specific exploitability was not tested.

Remediation: Review the upstream advisory, upgrade to a non-vulnerable version in an isolated branch, regenerate the lockfile, test all PDF/export workflows with untrusted content, and rerun the production audit.

SEC-003: High xlsx and Tiptap Dependency Advisories

High - Confirmed

The current audit identifies direct xlsx and the Tiptap chain as high. The xlsx audit data includes Prototype Pollution and ReDoS advisories and reports no automatic fix. Feature-specific exploitability was not tested.

Remediation: Replace or upgrade xlsx using supported vendor guidance; enforce workbook size/time/resource controls. Upgrade Tiptap packages as a compatible set, test editor workflows, and add production dependency-audit gating to CI.

Retest

Rerun npm audit --omit=dev --json after remediation and security-regression-test affected PDF, spreadsheet, and rich-text workflows.

Detailed Finding: SEC-004

Incomplete HTTPS Response-Header Baseline

Medium - Observed

The standard frontend/nginx.conf declares CSP, X-Content-Type-Options, X-Frame-Options, Referrer-Policy, and Permissions-Policy. The HTTPS configuration mounted by docker-compose.https.yml, frontend/nginx.https.conf, defines CSP but not this broader baseline or HSTS.

Impact: HTTPS deployments may lack intended anti-sniffing, frame-embedding, referrer, and browser-feature restrictions. An upstream gateway may compensate, but that was not validated.

Remediation: Centralize the header baseline in a shared include for HTTP and HTTPS profiles. Enable HSTS only after verifying the application is exclusively accessible through valid HTTPS. Retest headers on application, API, and error responses at the deployed gateway.
